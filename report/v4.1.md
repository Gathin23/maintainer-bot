# maintainer-bot v4.1: fixes from the 22 Oct live runs

The seven fixes asked for after Rounds O and Q (`~/Arsenal/cleanyourtv-launch/round-o.md`). Each one is tested,
and all of them were replayed on the day's live reviews.

## What changed

1. **Add-ons.** `addons/*/gradle/wrapper/gradle-wrapper.jar` is no longer a "prebuilt binary": the add-ons CI
   runs `./gradlew` (#870, #872, #936, #971). Any other jar or APK is still flagged. A PR that already is an
   add-on never gets the "send it again under addons/" invitation: the prompt says to judge it on its merits,
   and if the model still says "addon" the policy holds it instead (#870, #984).
2. **Conflicts → a rebase ask**, regardless of the model's verdict or confidence (the rule Gathin approved).
   The ask names the files: those both the PR and main changed since they parted, taken from two compare calls
   with nothing checked out. README table conflicts count too. Exceptions: the always-maintainer paths, Android
   core packages, and a confident close/showcase/addon, where the PR is closing anyway.
3. **Leans.** When a PR goes to the maintainer and the model (or, when the model held, the second opinion)
   leans one way, the comment's first line says so ("… needs **a maintainer decision** · Leans: merge (72%)")
   and the PR gets `bot-leans:merge`, `bot-leans:rework` or `bot-leans:close`. The bot owns these labels and
   removes them once the PR is decided.
4. **Duplicates.** The bot looks at earlier open PRs and at PRs merged in the last 7 days whose title is close,
   or which name the same issue (#N in the title, or "fixes/closes/for #N" in the body). It also checks main's
   last 7 days for the same files, and whether what the PR adds is already on main.
   - **Strong:** a shared file, plus the same issue, a near-identical title, or half the same added lines. Of
     two open PRs, only the later one is the duplicate, and a stacked series is not a duplicate.
   - **Policy:** if the model says close, the bot suggests "close"; otherwise the PR goes to the maintainer as
     "likely a duplicate of #N". A weaker match is only noted in the comment ("Possibly related").
5. **No invented hard flags.**
   - #982's `pm hide` came from a wrapped README sentence ("…  block YouTube ads"). `pm hide`/`block` now has to
     be a command on a package. In a list file's header, an apply instruction also counts ("Use `pm hide`
     instead"), but a mention ("we tried pm hide once") does not.
   - Permissions and network use are read only from code lines, not from XML, `//` or javadoc comments.
   - Every hard flag carries the diff line it came from (`evidence`). A test checks that each quoted line is
     really in the patch, and the Checks list shows it.
6. **Refusals** (#753, #830). The PR gets "Couldn't review this one automatically; it goes to the maintainer"
   plus `needs-maintainer`, instead of no comment at all. The next push or sweep tries again.
7. **Android core packages** (cleanyourtv #884, main 22dc48fe). The regexes are copied from
   `tools/recovery.py`, so a list naming one gets a rework ("remove X: core packages must stay enabled (#884)").
   The look-alikes that tested lists use (calendar, contacts, userdictionary and blockednumber providers,
   settings.intelligence, …) stay allowed; the same CORE and NOT_CORE lists as `tests/test_core_packages.py`
   are tested here.

Also fixed while replaying: "main at time T" now follows main's first-parent line (`--first-parent`). Without
it, the replay sometimes took a contributor's branch commit as main and missed facts like "edits a list on main".
The same helper fed the v4 backtest's facts, so a few of its fact snapshots may have been off.

Tests: 115 pass (`python -m unittest discover -s tests`): 20 new in `tests/test_v41.py`, plus the earlier ones
updated.

## Replay of the day's live reviews

Each v4 sticky stores the model's judgement (verdict, confidence, critic, second opinion). For the replay
(`scripts/replay_v41.py`), each PR was rebuilt at the commit the bot reviewed, with main as it was at that
moment, from a bare clone (`git merge-tree` for conflicts, nothing checked out or run). The facts were then
recomputed with v4.1 and the v4.1 policy run on the stored judgement, so any change comes from the fixes alone.
CI failures, a live-only fact, were carried over from the sticky.
